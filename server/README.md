# 本地开发服务

当前服务同时承载三类相互隔离的接口：

- 业务接口：SQLite 保存项目、成员授权、约定、材料、事项、费用、命令回执和审计，是 M2 的服务端事实源。
- 身份与附件接口：微信登录码换取短期业务会话；原件分块上传、校验并按项目权限私有读取。
- AI 接口：SQLite 保存 AI 输入快照（包括选定图片）、知识版本、模型输出和人工决定审计。

服务默认绑定 127.0.0.1，仅供本机开发和自动测试，不能直接用于多人线上体验。小程序现有页面尚未接入业务接口。

## 启动

使用 Node 24。将根目录 .env.example 复制为 .env，在本机编辑：

- DEEPSEEK_API_KEY：填写重新生成的模型密钥，只留在服务端。
- DEEPSEEK_MODEL：所用账号实际支持的模型名称，默认 deepseek-flash。
- AI_SERVICE_TOKEN：独立随机凭证，至少 32 字符；它不是模型密钥。
- DATABASE_PATH：默认 data/renovation.sqlite。
- ATTACHMENT_STORAGE_PATH：默认 data/attachments；必须和数据库一起放在持久磁盘并纳入备份。
- WECHAT_APP_ID / WECHAT_APP_SECRET：必须同时配置，只留在服务端。服务端用登录 code 换微信身份，绝不向小程序返回 session_key。
- BUSINESS_DEV_IDENTITIES_JSON：M2 本地身份列表，每个身份使用独立的 32 字符以上 Bearer token。示例：

```env
BUSINESS_DEV_IDENTITIES_JSON=[{"token":"owner-local-token-change-me-123456","id":"owner-dev","displayName":"负责人"},{"token":"family-local-token-change-me-12345","id":"family-dev","displayName":"家人"}]
```

运行 `npm run server`。小程序首页打开 AI 工作台，在连接设置中填入本机地址 `http://127.0.0.1:8787` 和 AI 服务凭证。该地址仅适用于同机开发者工具；真机需另行配置 HTTPS、微信合法域名和真实身份鉴权。开发者工具中的本地网络调试设置需按工具实际版本配置。

不要把 .env、数据库或用户图片提交 Git。数据库目前没有应用层加密和自动清理；真实用户上线前需要补数据保留、删除、备份和访问控制。

## 业务接口

业务 token 与 `AI_SERVICE_TOKEN` 独立，服务端从 token 解析身份，拒绝客户端自报角色。测试身份适配器只用于本地自动测试。配置微信 AppID/Secret 后，`POST /v1/auth/wechat` 接收一次性登录 code 并签发 12 小时随机业务会话；数据库只保存 token 摘要和微信身份摘要。登出或过期后业务请求立即失效。

- `GET/POST /v1/projects`：列出或创建当前身份可访问的项目。
- `GET /v1/projects/:id`：读取项目。
- `POST /v1/projects/:id/commands`：执行业务命令。
- `GET /v1/projects/:id/objects/:kind[/id]`：按授权范围读取业务对象。
- `GET /v1/projects/:id/audit`：负责人读取审计。
- `POST/GET /v1/projects/:id/attachments`：登记附件或按业务对象列出附件。
- `PUT /v1/projects/:id/attachments/:attachmentId/chunks/:index`：上传不超过 5MB 的分块。
- `POST /v1/projects/:id/attachments/:attachmentId/complete`：校验大小和 SHA-256 后确认原件。
- `GET /v1/projects/:id/attachments/:attachmentId[/content]`：逐次鉴权读取元数据或原件。

每个写命令必须带 `requestId`；同一身份、同一 requestId 和相同规范化输入返回原回执，输入不同返回 409。修改既有对象时带 `expectedVersion`，版本过期返回 409。成员范围、资源范围、项目归档状态和负责人专属动作均由服务端判断。组合变更和确认入库在同一 SQLite 事务中更新相关事实、审计及命令回执。

`member.put` 是本地开发的成员数据入口，不是邀请产品流程；邀请、撤销链接和在线分享属于 M5。

## 附件与同步边界

- 图片原件上限 20MB；音频和普通文件上限 50MB；音频须提供不超过 5 分钟的时长。
- 每个附件有独立的 `pending_upload / failed / ready` 状态。分块按序号和偏移校验，同一分块可安全重传；完整性失败保留元数据并允许替换分块后再确认。
- 原件没有公开 URL。读取时重新检查项目成员状态、资料领域和具体 record/agreement/material/issue/expense 范围；成员撤销后不能再读取。
- 小程序客户端已提供微信会话、2MB 分块上传、私有下载、持久文件草稿和冲突保留模块。批准、确认入库、复查、权限与负责人移交不进入离线队列。
- 当前 `LocalAttachmentStorage` 是本机和单机部署适配器。多实例部署必须换成对象存储实现；容器临时目录不能保存业务数据库或原件。

仓储和附件存储均有显式接口。推荐上线目标为微信小程序 + CloudBase 云托管 + MySQL + 私有 COS；本地 SQLite 和文件目录继续作为开发适配器。平台账号就绪后再实现并实测云端适配，避免在没有环境的情况下伪造通过。

## AI 调用流程

选择任务 → 明确选择资料及图片 → 服务端保存快照 → 检索本地知识卡 → 执行任务 Prompt → 校验 JSON 和引用 ID → 保存结果 → 人工采纳或不采纳、记录纠正。

任务覆盖记录整理、材料核对、图片观察、整改辅助、咨询整理、预算辅助、项目总结。采纳只改变分析决定、写入明确的业务草稿或保存报告版本，不批准费用、不自动发布咨询或总结、不采用执行预案、不形成正式复查或关闭事项。引用 ID 校验不能证明模型语义正确；AI01—AI07 已分别完成公开/合成小样本真实模型基线，真实工地和真实项目分布仍需单独评测。

整改辅助使用 `proposal / review` 两种显式模式：前者经人工复核后只新增待选预案，后者只保存复查参考。咨询整理使用 `prepare / response` 两种显式模式：前者只创建未发布咨询草稿，后者逐题整理已回填回复，只有人工标为“转为待选预案”的映射才会创建预案，并同步原回复状态以防重复转换。四种模式都锁定来源和目标版本，保留原模型结果、人工复核、图片引用及幂等应用记录。

预算辅助使用专用参数契约：模型只提取需求量、损耗、是否已含损耗、包装规格和整包单价，并保留来源、冲突与未知；负责人确认后由本地整数精度规则计算总需求、库存/在途/待核实资源缺口、整包数量和金额。采纳只保存估算版本及费用事实快照，不创建采购、批准或付款。材料、库存、使用、采购或到货变化会改变来源版本，旧分析不能继续写回。

项目总结使用专用五分区契约：用户先固定工序、房间、日期和截止时间；事件按发生时间筛选，问题、材料和费用等当前状态保留到截止时点。负责人逐节编辑并确认后只保存报告版本及来源/问题/费用快照，不改变业务状态。完整备份、离线 HTML 和 CSV 包含确认后的报告；保存报告不会自动创建分享。

材料到货核对使用专用契约：一次任务恰好关联一个材料和一个到货批次；品牌、型号、规格、数量四个字段必填，可选批次、生产日期和外观。只有与本材料关联的已批准约定版本能支持“一致/差异”；采购所绑定、后来被替代的历史已批准版本仍是该采购批次的有效基线。没有正式基线只能记录观察或未知。采纳时必须提交逐字段人工复核；原模型输出和人工版本分开保存。小程序再写入独立 `MaterialCheckRecord`，不会产生库存事件。

每次模型执行记录实际返回模型、供应商请求 ID、耗时及 token 用量（供应商返回时）。真实评测使用 `npm run eval:material`、`npm run eval:m6b`、`npm run eval:m6c`、`npm run eval:m6d` 或 `npm run eval:m6e`，必须显式传 `--confirm-live`；工具顺序调用、不自动重试、每例落盘并按外部价格快照估算费用。材料分批结果可使用 `npm run merge:material-eval` 合并。报告不保存图片 data URL、图片路径或输入资料正文，格式见 `evaluation/README.md`。文本与合成小样本只验证结构和产品边界，不能替代真实视觉、预算、交接或施工验收。

`deepseek-flash` + Prompt `2026-09-26.2` 的首轮真实 API 合成视觉评测为 7/7 用例、111/111 断言、6/6 关键用例通过，最终采用 15,041 token，按当时空闲价估算人民币 0.02665088 元。当前 Prompt `2026-09-27.3` 仅补充历史已批准约定规则，尚未重新执行付费视觉评测。该结果没有覆盖真实工地图片，也不等于供应商最终账单。

接口包括 `POST/GET /v1/ai/jobs`、`GET /v1/ai/jobs/:id`、`GET /v1/ai/jobs/:id/sources`、`POST /v1/ai/jobs/:id/decision`、`POST /v1/ai/jobs/:id/cancel` 和 `POST /v1/ai/jobs/:id/retry`。小程序使用 `POST /v1/ai/jobs?async=1` 立即取得运行任务并轮询；不带 `async=1` 的同步方式继续供本地兼容测试使用。除健康检查外均使用 AI Bearer 服务凭证。

同一 requestId 与相同输入会复用原任务，不自动重试模型；输入改变返回 409。运行中可取消，服务端会先保存取消状态再尽力中断上游，晚到结果不会覆盖取消状态；取消仍可能产生供应商费用。失败或取消后可显式按原输入与知识快照创建关联重试任务，成功任务不能重试。每日每项目最多 20 次，并发最多 2 次，失败、取消和重试均计数。服务重启将运行任务标为失败而不自动重放。

## 验证及待完成

`npm test` 使用模拟模型和本地 HTTP、SQLite 验证流程，不调用真实模型；`npm run typecheck` 检查类型。当前项目共 113 项自动测试，其中服务端测试覆盖业务事务、短期会话、登出/过期、微信适配器秘密隔离、附件分块与重试、校验失败、私有读取、撤权、故障回滚、AI 专用任务契约、后台取消、显式重试、日限额、人工复核、评测门槛及费用计算；其余测试覆盖本地业务、预算确定性计算、项目总结范围与时间过滤、AI 幂等写回与来源失效、备份恢复、可移植资料和页面静态契约。

尚未验收：真实 AppID 双账号登录、云端 MySQL/COS 适配、微信开发者工具、跨设备与真机、真实工地图片模型质量、供应商控制台账单核对、实际摄像头。当前知识卡只是小规模检索底座，不是已核验的行业知识库。没有接入通用 Agent 框架。
