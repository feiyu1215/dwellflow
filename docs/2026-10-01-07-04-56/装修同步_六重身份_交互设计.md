# 六重身份 · 交互设计

> 2026-10-02
> 前置文档：《产品定位：一个后台，六重身份》《AI 七场景：贯穿还是场地（终版循环）》《场地清单》《结构模型 v4》。
> 本文回答一个问题：**六重身份各自怎么"出场"、怎么交互。**

---

## 0. 总纲：六重身份的交互区别，本质是"谁发起"

| 身份 | 谁发起 | 出场隐喻 | 类比 |
|---|---|---|---|
| 1 记录本 | **在地**（一直在，不发起） | 房间里贴着的便签 | 工地墙上的记事纸 |
| 2 分析员 | **就位**（对象旁边等你） | 批次旁/问题旁的小标记 | 贴在货物上的核对单 |
| 3 哨兵 | **主动**（它来找你） | 场地顶部的哨兵条 + 场景里的小旗 | 工地门口的告示旗 |
| 4 参谋 | **应邀**（你问它才摆选项） | 桌上摊开的对比图纸 | 桌面上并排的两版方案 |
| 5 管家 | **随叫**（呼吸点常在） | AI 呼吸点 | 随叫随到的工友 |
| 6 交接官 | **按需**（收尾才出现） | 概览页的"交接包" | 交房资料袋 |

**所有身份共用**：终版循环（人表达→AI 定位→AI 代办→就地拍板→落点跳转）、手稿亮底视觉、结果卡四要素（做了什么/对象/范围/落点）、AI 失败不阻断人工路径。

---

## 1. 记录本 · 在地

- **在哪**：房子场地（便签贴在房间里）、料场/告示板的对象卡里（记录史 tab）。
- **入口**：点房间里的便签纸片；或任何对象详情里翻它的记录时间线。
- **循环**：随手记（文字/拍照/语音）→ 自动挂 (房间, 工序) → **归属不确定就标"归属待补"，绝不自动归当前工序**（K02）→ 想改 = 新版本，旧版永远可追溯。
- **关键界面件**：
  - **便签贴片**：纸绘小纸片贴在场景里，**便签数量微调该房间的覆盖度色**——记录本身参与上色；
  - **时间线**：对象详情里按时间的纸感列表，每条带来源（谁、何时、哪个版本）。
- **红线**：记录不可静默改动；无附件记录 ≠ 风险，只显示"无附件记录"。

## 2. 分析员 · 就位

- **在哪**：料场批次旁（材料核对）、告示板问题旁（整改辅助的姐妹件"观察"）、便签旁（记录整理）。
- **入口**：对象旁的**就地小标记**（chip：批次卡右下"核对"、便签右上"整理"）。
- **循环**：点标记 → **第一屏 = 范围预览**（AI 将看到这份资料 + 批准基线，可增删）→ AI 起草 → **结果卡**（差异逐条：对上了 = learned 绿，不符 = 标注差异明细）→ 人改 → 写回 → 产物落在原对象。
- **关键界面件**：范围预览卡（K03 教训变设计）、差异高亮结果卡、二次核对入口。
- **红线**：产物先复核再写回；重复操作不产生重复记录（幂等）。

## 3. 哨兵 · 主动（唯一"它来找你"的身份）

- **在哪**：两处出场——
  1. **哨兵条**：进任何场地，顶部先看一眼（纸绘小旗 + 数字），点开是提醒清单；
  2. **场景标记**：出问题的位置在场景图上插一面小旗（卫生间门口一面 amber 小旗 = 闭水试验超期未复查）。
- **入口**：不需要唤起。它基于**已记录事实**主动出现：超期（做完 X 天没看到复查）、缺口（材料按工期要用但缺 N）、阈值（付款到批准额 90%）、积压（归属待补 N 条）。
- **循环**：后台规则扫事实 → 生成**提醒卡**（说清依据：哪条记录/哪个检查项；不足就标"待核实"）→ 人点卡 → **落点跳转**直达到该处理的对象 → 处理完旗子自动降色/收旗。
- **关键界面件**：哨兵条、场景小旗、提醒卡（事实 + 依据 + 前往按钮）。
- **红线**：只基于已记录事实与明确检查项说话，**措辞是"建议核查"，不说"有风险"**；不推断隐蔽结构。
- **视觉**：小旗是**画在场景里的**（同一笔触），不是系统弹窗——警报也是场景的一部分。

## 4. 参谋 · 应邀

- **在哪**：告示板（预案选项）、账台（估算参数）、图纸桌（方案版本对比）。
- **入口**：对象旁"给我选项"；或哨兵卡转介（"这个问题要处理吗 → 看看选项"）。
- **循环**：人表达处境 → AI 给 **2–3 个选项并排**，每个带依据来源和代价 → 人选一个或改 → 生成正式预案/估算草稿 → 走负责人确认流。
- **关键界面件**：并排选项卡（图纸桌上"两版图纸摊开"的隐喻）、版本 diff 视图、依据溯源（每个选项点开能看到它基于哪些记录）。
- **红线**：AI 不替人选；选项必须可溯源；估算靠程序计算，AI 只备参数。

## 5. 管家 · 随叫

- **在哪**：任何场地——AI 呼吸点常驻。
- **入口**：点呼吸点 → 表达卡（说 / 拍 / 贴）。
- **循环**（终版五步）：人表达 → **定位卡**（AI 猜意图和对象：候选 + 置信度，一键改判）→ AI 代办起草 → **就地拍板**（跳转到对象的确认页）→ **落点跳转**（"已写入料场 · 批次 #3 → 前往"）。
- **关键界面件**：表达卡、定位卡（候选改判）、跳转卡（结果卡四要素：做了什么/对象/范围/落点）。
- **红线**：点开是 2–3 张诚实任务卡，不是聊天框；听不懂就明说给候选；执行留痕进审计。

## 6. 交接官 · 按需

- **在哪**：项目概览页（普通页，不配场景）。
- **入口**："生成交接包"。
- **循环**：选范围（阶段/房间/日期）→ **范围预览**（包里会有哪些记录）→ AI 起草报告 → 人改 → 确认版本 → 导出（离线 HTML/CSV/JSON，可恢复）。
- **关键界面件**：范围选择器、纸感报告预览、导出卡（含"只含已确认记录"的声明）。
- **红线**：报告只纳入确认过的内容；版本留档；外发副本不可远程收回（如实告知）。

---

## 5. 一天的用户旅程（六重身份怎么接力）

> **早上**：进房子 → 哨兵条说"闭水试验超期未复查（第 3 天）" → 点卡直达卫生间；
> **上午巡场**：左右滑穿门 → 卫生间纯线稿（未开工）→ 拍照给 AI 看看 → 图片观察说"瓷砖还没铺，与记录一致" → 顺手在便签记一笔；
> **中午**：管家收到工长微信截图 → 粘贴 → 咨询整理成回复草稿 → 谈定后落到图纸桌留版本；
> **下午**：料场 → 新批次到货 → 批次旁"核对" → 范围预览 → 差异结果卡 → 拍板写回；
> **傍晚**：告示板 → 问题旁"给我选项" → 参谋摆两案 → 选一 → 负责人确认；
> **月底**：概览页 → 交接官按范围起草 → 导出交接包。

一天下来，六个身份各出场一次，**用户没有一次是"找功能"**——要么它就在对象旁边，要么它主动开口，要么它随叫随到。

---

## 6. 交叉检查（PRD 红线全覆盖）

| 红线 | 落点 |
|---|---|
| K01 范围一致 | 分析员/哨兵/管家所有入口携带 (stageId, moduleId, roomId) |
| K02 归属不漂移 | 记录归属不确定 → "待补"，哨兵主动催补 |
| K03 范围预览 | 分析员/管家/交接官第一屏都是范围预览 |
| K04 诚实入口 | 呼吸点=任务卡；对象旁=就地标记；无假输入框 |
| K06 完工语义 | 覆盖度上色=记录覆盖度；措辞"此前阶段/建议核查"，不说"已验收/有风险" |
| AI 失败不阻断 | 每个就地标记旁都有手工等效路径（按钮/表单），AI 挂了照常用 |

## ✅ 修正案（2026-10-02 晚 · 深度思考轻档质疑后 · 已定案执行）

大将军判："这交互不太 OK，偏离主旨。" 四层质疑结论：**方案把"内核的六种能力"翻译成了"前端的六套 UI"——错了。**

### 违反的三条自定原则
1. **内核是后台**：身份是内核能力分类，前端用户不该感知到"六个身份"；
2. **单一委派入口**（K04 教训）：设计里出现了呼吸点+就地chip+哨兵条三个入口形态，自相矛盾；
3. **图是场景**：便签贴片+小旗+chip 把巡场场景贴成仪表盘，沉浸感死亡。

### 修正提案：前端只留三样
| 元素 | 承载 |
|---|---|
| **巡**（穿门/左右滑） | 游览本身 |
| **场景对象**（点开=对象卡：动作+记录时间线） | 记录本（便签=场景内容）、分析员（卡内动作）、参谋（卡内"看选项"）、交接（概览页按钮） |
| **呼吸点**（唯一 AI 入口；被动=管家，主动=哨兵） | 管家 + 哨兵（呼吸点角标+卡跳场景，**哨兵条/就地chip/独立小旗全撤**） |

六重身份退回内核，作为"AI 在不同时机的发起模式"（在地/就位/主动/应邀/随叫/按需），前端零新增 UI 概念。

### 场景纯净性预算（新增设计纪律）
> 场景上只允许存在三类东西：**场景本身、对象（可点）、AI 呼吸点**。
> 任何新 UI 想上场景，先回答"它是对象本身吗？"——不是，就进对象卡或呼吸点。

### 自检清单（日后每版设计过一遍）
- [ ] 场景截图里非场景 UI ≤ 3 类
- [ ] 用户要学的交互概念 ≤ 3 个（巡/点/说）
- [ ] 每个 UI 都回答了"它是对象本身吗"
- [ ] 六重身份在界面上不可见（只在行为时机上可感）
- [ ] AI 入口只有呼吸点一个

> **执行状态（2026-10-02 定案）**：本修正案按"决策由思考定案"原则自行拍板生效。上文"原设计"部分（六套界面件：便签贴片/哨兵条/就地chip/独立小旗/结果卡/选项卡）全部**作废**，仅保留身份定义（作为内核 AI 发起时机的分类）与总纲思想。落地产物见《装修同步_巡场原型_v4_料场.html》——料场原型是修正案的第一块试验田，一次验证：非房子场地成立性、分析员就地入口（改放对象卡内）、哨兵（呼吸点主动形态）、场景纯净性预算。
