## 3. 核心决策与冻结项（务必遵守）

### 3.1 交互三原语（**冻结，禁止改动骨架**）
owner 亲自定的，是"AI 原生产品的交互内核"，不是顺手搓的：
1. **7×6 工序矩阵**——巡查主导航。纵轴=工序（水电/防水/泥瓦/木工/油漆/安装/软装 7 行），横轴=模块（6 列），深度=时态。
2. **四向手势导航**——左右滑切模块、上下滑切工序、点格进入巡查卡。
3. **悬浮 AI 助手**——常驻，不新增手势。

> ⚠️ 你能改的是**皮肤**（色阶/间距/圆角/字阶/质感），**不能动骨架**（导航结构、手势、信息层级、数据流）。这是 owner 明确划的线。

### 3.2 核心是巡查，不是场景选择
首屏必须是巡查入口（矩阵 / 进度），**不要**画成"选一个装修场景再开始"那种引导页。这是早期偏差，已纠正。

### 3.3 视觉语言：二维绘画，不要 3D（**全项目最重要的一条，详见第 7 节**）
> ⚠️ **措辞警告**：早期版本这里写的是"分层**写实**纪律"。**那是错的，已作废。**
> "写实 / 非写实"是我方自己造的二元框，owner 从头到尾没在这个维度上想。不要用这个词描述本方案。

owner 定下的取舍标准是：**好的设计不必写实，也不必纠结 2D/3D**。

- ✅ **可以用二维绘画表达空间**：手绘、插画、素描稿、纸绘线条、轴测（isometric，在二维上表现三维感）
- ❌ **不用 3D 模型** —— 真实理由是**做好 3D 难度太高、成本不可控**；要用就用网上公开素材（GitHub 等），而不是自己做
- 🟡 **卡通风是迫不得已的兜底**，不是目标方向

**空间视觉三层（2026-10-02 定稿，见 `装修同步_空间视觉三层方案.html`）**：
1. **选户型**（一室一厅/二室一厅/三室一厅）→ 自动出房间分布预览
2. **在这张图上巡场** —— 各房间状态不同（未开始 / 施工中 / 已通过 / 有缺陷）
3. **进到具体房间** → 2D 纸绘风房间，带轴测体积感

**巡查节点 ICON 是另外一层**（水电/防水/泥瓦…），跟空间图分开管，别混。

**素材策略（详见 `装修同步_公开素材调研_2026-10-02.md`）**：
- 首选路径 = **生成器（`laanlabs/openPlan3D`，MIT）生产几何** + 我们自己的纸绘语言渲染
- 它是"**资产工厂**"，**不是运行时依赖** —— 不进小程序（守住禁 WebGL/Three.js 的冻结线）
- 硬理由：小程序主包 2MB，带贴图 GLB 几 MB～几十 MB，塞不进去
- 巡查要动态着色 + 多户型切换 → **必须矢量**，位图不可用

## 4. 设计系统速查（Token）

小程序用 rpx，基准 750。括号内为 px 等量，便于设计稿对照。

**间距（4pt 网格，6 档）**
```
--sp-1: 8   --sp-2: 16  --sp-3: 24  --sp-4: 32  --sp-5: 48  --sp-6: 64
```

**字阶（6 级，宋黑对撞）**
```
--fs-display: 56   /* 宋体大标题 */
--fs-title:   40   /* 宋体标题 */
--fs-h1:      32   /* 黑体 H1 */
--fs-body:    28   /* 黑体正文 */
--fs-sub:     24   /* 黑体次要 */
--fs-cap:     20   /* 黑体说明 */
```

**圆角（4 级）**
```
--r-sm: 8   --r-md: 16  --r-lg: 24  --r-pill: 999
```

**色彩**
```
--bg:         #F6F5F2   /* 纸感暖白 */
--surface:    #FFFFFF   /* 卡面 */
--ink:        #1C1B19   /* 主文字，非纯黑 */
--sub:        #6F6B63   /* 次级文字 */
--faint:      #9C978E   /* 说明/图例 */
--line:       #E7E4DE   /* 发丝描边 */
--accent:     #0E7C66   /* 绿（原名 --green 值却是蓝 #0071e3，已改名修正） */
--accent-soft:#E7F1ED   /* 绿色浅底 */
--learned:    #14B8A6   /* 青点 = AI 已学会自主处理 */
```

**描边 / 阴影**
```
--hairline: 1rpx solid rgba(0,0,0,.06)
--shadow-card: 0 8rpx 24rpx rgba(0,0,0,.04)
```

**字体对撞（中文可行方案）**
- 宋体（衬线，Display/Title）：设计稿 `Noto Serif SC` / `思源宋体`；真机 `Songti SC`（iOS）/ `宋体`（Android）。
- 黑体（无衬线，正文/数据）：设计稿 `Noto Sans SC` / `思源黑体`；真机 `PingFang SC`。
- 中文无 italic，用**字重对比**替代（宋体 Bold 大标题 × 黑体 Regular 正文）。
- 全局只有"宋体标题 + 黑体正文"两种角色。

**单一视觉原子纪律**
- 全 app 只有**一种视觉原子 = 绿色圆角方块**（矩阵格/焦点/状态都用它的变体）。
- 禁止第二种装饰语言（无 logo 墙、无渐变卡片、无第二种强调色）。

> 完整可直接粘贴的 `app.wxss` 见交付文档第 4 节，不要重新发明。

## 7. 踩坑记录 / 偏差修正历史（**重点，别重蹈**）

这些是本项目的"血泪史"，每一条都是 owner 当面纠正过的。每一条都值得你开工前读一遍。

### 7.1 首屏误画成"场景选择"
早期把首屏画成"选一个装修场景再开始"的引导页。owner 指出核心是**巡查**，入口必须是矩阵/进度。→ 已改。

### 7.2 "工地照片必须真实"是错的
曾写"工地照片必须真实"。owner 纠正：**深海是风景、工地不是**——工地（施工进行中的现场）不必写实、不必实拍。但注意这条**不能扩到房子**（见 7.5）。

### 7.3 空间定位不必是房子
曾说"空间定位感要结合房子"。owner 纠正：空间定位是**整体方位感**，矩阵本身就是空间定位系统，抽象即可；能和房子结合好就用、结合不好就别硬上。→ 矩阵即底图，不必是房子。

### 7.4 参考工具清单不必四处去扒
曾列了一长串参考工具（酷家乐/住小帮/Fieldwire/MagicPlan…）说要逐个研究。owner 质疑"真的有必要吗"。→ 改为"风格来源标注"，说明视觉语言从哪借，**不是必须逐个去扒的清单**，实际交付不依赖访问它们。

### 7.5 非写实误推到整个房子（**最严重的一次**）
曾把"非写实/示意风格"应用到**整个东西**，连房子/建筑/主体场景都让别写实，还画了水电/防水/泥瓦三张当"全部"。owner 严厉纠正：**非写实只适用于节点 ICON，不能用到整个房子；房子/建筑/主体场景必须真实写实；那三张只能当 ICON，做不了别的。** → 已落实"分层写实纪律"（第 3.3 节），这是当前版本的核心结论。

> 一句话红线：**节点 ICON 才走非写实，房子必须写实。任何把"非写实"推广到主体场景的念头都是错的。**

### 7.6 ARDOT batch_edit 焦点卡语法错误
画布阶段曾因 `strokes` 数组结构括号错位（颜色对象后缺 `]` 即接 `strokeWeight`）导致"Insert failed: Failed to parse node data"，连带两次"Insert: parent not found: fc"。该批其余节点成功，焦点卡未建成。因 owner 随即要求放弃画布改文档，未回头修复。→ 续建画布时注意 batch_edit 的 JSON 结构完整性。

### 7.7 三次在"写实"上转错弯（owner 连纠正三次，务必读完）
这是本项目最高频的错误。owner 从头到尾**没有在"写实 / 非写实"这个维度上想过问题**，是我自己造了这个二元框反复套。

| 轮次 | 我错在哪 | owner 的原意 |
|---|---|---|
| 第一次 | 写"工地照片必须真实" | 深海是风景、工地不是。工地照不必实拍 |
| 第二次 | 纠枉过正，把"非写实"用到整个东西，连房子都让别写实 | 房子要成其为房子，抽象方块只能当 ICON |
| 第三次 | 又把方案框成"2D / 3D / 卡通风"三选一，还纠结"写实" | **好的设计不必写实、也不必纠结 2D/3D**。可用：插画/手描稿/素描/纸绘线条/中世纪机械手稿。不做 3D 的真实理由是**成本高**，不是不好 |

**记住**：如果发现自己又在写"写实还是非写实"、"要 2D 还是 3D"，停一下——那说明又掉进同一个坑了。正确的词是**绘画语言**：手绘、插画、素描、纸绘、轴测。

## 10. 关键约束与红线（owner 定的，别碰）

- **不替 owner 决定事实**：技能栏写什么、有没有某段经历、素材从哪来——只写能验证的，他不确认的留白让他自己填。

- **相关性 > 形式规范**：形式是工具，相关性是目的。绝不拿形式规范（倒序/一页/某种排版教条）反压内容判断。
- **先查再问**：能用工具/文件查到的先查完再开口，别让 owner 自证。
- **认错要快**：被指出问题就认，划掉错的，立刻给正确方向，不辩解。
