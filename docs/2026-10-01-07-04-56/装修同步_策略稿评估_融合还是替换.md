## 一、合法性审视：这份稿子该不该被当回事

**该。三条硬证据：**

1. **同源不同枝。** 外稿开头自述"用户 2026-10-02 提出交互设计方向（附 A–H 参考站清单 + Interaction Loop 判据）"——和我们收到的是同一份原始方向。它不是外来体系，是同一次思考在"现有代码落地"这一侧的产物。
2. **诊断建立在代码事实上，不是印象分。** §一指出 dashboard 是"iOS 设置页模仿秀"（`#f5f5f7` 灰底白卡 + 药丸按钮，WXSS 注释自述 "iOS Setup-inspired"）、"构图只有一种：卡片堆叠"、"动效不携带状态"、"没有主动词"——每条都落到具体样式事实。这是我们没做过的功课（我们做的是概念原型，没碰现状代码）。
3. **红线全兼容。** §九红线：不引依赖、不改四向手势语义、AI 不伪装输入不入库、语义红线继承（顺序≠完工等）——与 PRD 四条红线（K01/K02/K04/K06）零冲突。

**结论：它有独立存在价值，删掉它是损失。**

## 二、方案空间：融合、二选一，还是各管一段

### 2.1 先看清两者管的不是同一层

| | 我们已定案的体系（v4 及此前） | 外稿 |
|---|---|---|
| 回答的问题 | 巡场/场景/AI 交互**该长什么样**（概念层） | 现有小程序**怎么从卡片堆里救出来**（落地层） |
| 主战场 | 巡场原型 v2/v3/v4、场地系统、素材四路线 | `pages/dashboard` 现状改版、B1–B4 批次、CHG 流程 |
| 产物形态 | HTML 原型 + 决策文档 | 变更登记 + 工程验收标准 |

两者对"Interaction Loop""世界/内容两层""主动词统治"的理解完全一致（外稿 §二、§四 ↔ 我们的 Loop 判据、Terrain/Reading 两段、巡场主动词）。**分歧只在三处**，见 2.2。

### 2.2 三处分歧的逐一裁决

**分歧① 主动词：外稿"推进" vs 我们"巡场"。→ 保巡场，推进降级为动作。**
"推进"是工序本位的——它统治不了记录、核对、AI 委派这些"不推进也在发生"的事；"巡场"是空间本位的，逛和办都在场。且"巡场"出自你本人的定义，外稿的"推进"是它自己推的。但外稿 §十二第 4 条"推进仪式"（阶段变更是有事实依据的业务操作，保留确认步骤）本身是好设计——**收编为告示板/对象卡上的一个动作**，不当地基。

**分歧② 空间形态：外稿"一维纵向勘测卷"（§十，反对自由画布） vs 我们的房子+房间+事务地块。→ 各管一段，互不替代。**
外稿的"轻空间"三条映射（**位置=归属、密度=证据量、距离=进度**）在阶段时间轴上成立，正好接管我们**房子总览页的流程列表交互**——我们 v4 总览现在是普通列表，外稿 B1 的"拖拽磁吸 + 锚定展开 + 顶部读数"就是这层列表的正确交互形态。而房间下钻、料场/告示板等事务场地是外稿没覆盖也没否定的部分（它的 B4 户型点位与我们 v3 穿门方向一致）。**外稿反对的是"自由 2D 画布"，我们从来没要做自由画布——这点不冲突。**

**分歧③ 美学：外稿"勘测/仪器/账本，零插画"（§十三） vs 我们的手稿亮底场景。→ 手稿亮底为主线，账本风明确登记为降级路线。**
外稿的理由是"小程序平台做不了 Awwwards 级渲染，硬追必成四不像"——这个约束我们本来就接受了（B 路线的定论就是"小程序只吃 2D 静态成品"，不做实时渲染）。所以这不是真冲突：**素材管线（CC0 + Blender）产出静态高清 2D 场景图，满足外稿的技术边界；若素材管线最终跑不通，外稿的账本风是诚实且能打的 fallback**——外稿自己也写了"手绘插画给不了的话，那是买素材的活，不属于本路线失败"。两条路线在同一边界内，只是赌注不同，都留着。

### 2.3 必须吸收的四样（这是外稿最有价值的部分）

1. **状态机 + Motion 规则（§六）**：区域状态机（未开始/此前阶段/正在进行/待确认/受阻）+ "每个状态有确定视觉本体 + 状态词必须以文字存在 + 禁孤立装饰动画" + 动效时长 4 档。我们的原型目前动效全凭感觉，这套规则直接补齐。
2. **HITL 空间化（§十一）**：幽灵卡=AI 草稿（虚线/半透明，人工转正才变实线证据点）、AI 任务=工作对象（发起→工作中→待复核→转正/驳回）、环节级 AI 在场开关（不做全局滑杆）。**与我们 v4 的对象卡+呼吸点严丝合缝**：幽灵草案不是新 UI 类，是"对象"的一种状态（AI 草稿态），不违反场景纯净性预算；呼吸点=主动发起，工作对象=被动挂在场内。这是比我们"五步循环"更完整的 AI 生命周期表述，直接并入。
3. **像素级四规格（§十三）**：视觉令牌表 / 状态覆盖表 / 动效规格表 / 对齐断言——"精致不靠眼睛验收，靠扫描"。外稿对"非精细化"的病因诊断（**中间资产缺失，每个像素都在即兴**）与我们素材侧结论（喂料三件套 > 看成品图）同源互证。这套规格对巡场原型同样适用。
4. **工程流程（§八、§十四）**：B1–B4 每批独立可展示可回退、开工前先交规格、CHG 登记、程序化断言验收。我们的概念要落到代码，就得走它的批次与验收纪律。

### 2.4 不吸收/暂缓的

- §十五的 6 个待确认问题：按既定原则自己定——①主动词=巡场；②轻空间=认可（用于总览）；③B2.5 并入 M8C=认可；④手势边界=认可；⑤观察卡收进面板；⑥先 M8B-3A 缺陷收口再 B1（数据缺陷优先于视觉改版，PRD 既有原则）。
- "推进"作为全局主动词（裁决见 2.2①）。

## 三、执行质量收束：融合后的地图

```
概念前沿（我们）                      落地路线（外稿）
巡场主动词 · 三手势 · 场地系统   →   B1 概览世界化（总览流程=一维勘测卷）
手稿亮底 + 覆盖度上色（素材管线） →   状态机视觉 + 精细化四规格（B1 前置）
对象卡 + 呼吸点 + 五步循环       →   B2.5 HITL 空间化（幽灵卡/工作对象/在场开关）
房间下钻 · 料场/告示板/监控屏    →   B4 空间点位（M8E 省力版）
```

**一句话结论：外稿是"同一方向的工程半场"，全盘收进；它与我们冲突的三处，两处是分工误会（轻空间 vs 场地、账本风 vs 手稿亮底），一处真裁决（主动词保巡场）。没有任何已定案东西需要被替换掉；需要换掉的只有我们总览页的列表交互（换成勘测卷）和裸奔的动效（换成状态机+四档规格）。**
