## 1. 评判标准：这次唯一的尺子是"和巡场交互的配合度"

拆成三条，逐条打分：

1. **空间连续性**——能不能让"房子 → 房间 → 环节"处在同一个视觉坐标系里。这是巡场的命根子。
2. **精度上限**——能不能撑得起"高精度、更牛逼的素材"（你的原话）。
3. **量产一致性**——房间一多（6 间 × 几种户型），还能不能是"一个妈生的"。

## 2. 四条路线

### 路线 A｜现成等距/插画整套（拿来即用）

- **来源**：Isometric.online（MIT）、DrawKit（MIT）、ManyPixels（免费无署名）、SVGRepo Living Room（CC0，429 限流待重试）
- **空间连续性：中**。等距视角自带空间感，但整套是**别人的**整套——房间组合、户型种类由不得我们，加一种户型就断档
- **精度：中**（矢量可放大，细节密度一般）
- **一致性：高**（同一作者画的）
- **代价：最低**，今天就能换上
- **定位：过渡方案**，在 B 没搭好之前救急

### 路线 B｜CC0 3D 素材 → 离线渲染成高清 2D（精度上限最高）⭐

- **来源**：Quaternius Ultimate House Interior（CC0，123 件门窗/厨卫/沙发/床/灯）、`ToxSam/cc0-models-Polygonal-Mind`（CC0，991 个 GLB 含整套室内）、`gltf-research-scenes`（仓库 MIT，但 CC0 与 CC-BY-3.0 混装，逐场景核）
- **做法**：Blender 里固定一台正交相机 + 统一打光 → 脚本批量渲染等距高清图（WebP）→ **小程序只吃 2D 成品**
- **红线不破**：渲染发生在开发机，小程序里没有任何 3D runtime——"不引入 Three.js/WebGL"的冻结项完好
- **空间连续性：最高**。等距坐标 = 天生一个坐标系；任意组合房间 = 户型无限；固定相机 = 全套必然一个妈生的
- **精度：最高**。渲染分辨率自己定，2x/3x 图随便出
- **代价**：搭一次渲染管线（Blender 批量脚本），一次性投入约 1–2 天
- **定位：终稿主力**——"高精度更牛逼的素材"的正解就是这条

> **回应你那句"手绘稿和交互没那么配合"**：对。但问题的根子不在"手绘"，在**手绘物件没有空间坐标系**——单件再好看，也拼不出"房子→房间"的连续空间。3D 渲染出的等距场景，每件家具天生站在同一个坐标系里，这正是巡场要的东西。

### 路线 C｜手绘物件库当零件（点缀，不当主场景）

- **来源**：**Kitbitz Interior**（🟢 官网实核：2,000+ 手绘 SVG，CC0，免署名，有 Figma kit 和组件，**还提供 MCP 可直接让 AI 工具取件**）、Open Doodles（CC0）、DrawKit 手绘系列（MIT）
- **空间连续性：低**（当主场景时）——这正是你指出的问题；**但当零件时配合度很高**
- **定位：零件层**——空状态插画、AI 入口的视觉同源小物、引导图
- **精度：中**

### 路线 D｜户型生成器（户型骨架层）

- **来源**：`openPlan3D`（MIT，🟢 README 已核验：导出 SVG/DXF/PNG）、`FloorplanTransformation`（MIT，偏老）
- **配合度：高（仅限户型层）**——选三室一厅/二室一厅 → 参数化出几何正确的户型 SVG → 交给 B 或 C 的视觉语言去渲染
- **定位：图纸层**，不是场景图。娃娃屋视角/户型切换的骨架由它出

## 5. 推荐组合（主次明确）

> **B 为主力 + D 出户型骨架 + C 做零件点缀；A 只在 B 管线没搭好之前救急。**

一句话：**场景精度找 B，户型骨架找 D，零件点缀找 C，A 是备胎。**

分工落到产品里：

- **娃娃屋/户型层** ← D 生成 SVG 骨架
- **房间场景（巡场的主体）** ← B 渲染高清等距图
- **空状态/AI 入口小物/引导图** ← C 手绘零件
- **原型现在的手写线稿** ← 留作结构验证，等 B 出图后整体替换
