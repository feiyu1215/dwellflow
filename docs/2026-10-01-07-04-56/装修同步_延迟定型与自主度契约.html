Round 4 · Deferred Typing & Autonomy Contract

装修同步 · 不要空间，要「延迟定型」

关于 Milanote 能不能结合空间，我的判断是不结合——但 Milanote 里最值钱的三件事，一件也不需要空间。这三条加上 CopilotKit 那套术语，正好补上我上一轮提案缺的两个洞。

Verdict
空间不作主语，只作可选皮肤。Milanote 迁移的三件事里，没有一件依赖坐标。

三条理由：① 自由画布必需的单指 pan，和你冻结的四向 swipe 抢同一个手势槽，这是硬冲突不是审美；② 你自己的判据是 Loop 不是 3D，得先证明 Loop 成立，再谈容器；③ 小程序 Canvas2D 没有 DOM 命中测试，做完你得到的是一个自己维护的迷你引擎。

01

为什么我不主张加空间

三条，第一条是硬冲突
A
手势槽已被征用，这是物理级的冲突
你定过：左右滑切模块、上下滑切工序。而「一个可以自由探索的空间」的最低门槛是 单指拖拽平移镜头（pan）。同一根手指在屏幕上做同一个动作，不可能既切模块又拖镜头。
出路只有两条：pan 吃掉 swipe → 你的骨架没了；swipe 吃掉 pan → 画布不能拖，那就不是空间，只是一张静态图。
第三条看上去可行的是「加一个编辑键先切换模式」，但那等于在「逛」之前先「换挡」，正是 Bruno Simon 那条 One Primary Verb 的反面。
B
你自己给的判据是 Loop，空间只是容器
「真正高级的设计往往不是 3D，而是 Interaction Loop」。这句话已经把判定顺序定死了：先证明 Loop 成立，再决定它长什么样。现在 Loop 只在一个 HTML 演示里闭合过，还没在真机上验。
而且 7×6 这个矩阵本身已经是一个坐标系——工序是纵轴、模块是横轴、时态是深度。它不是没有空间感，它是把空间压进了语义。San Rita 的真东西是「terrain 承担导航」，不是「terrain 要有海拔」。
C
小程序这笔账很不划算
Canvas 2D 没有 DOM 命中测试：42 个 hotspot 要自己写 hit-test、相机、惯性滚动、边界回弹、双指缩放。而且 touchmove 里的 transform 必须走 WXS，否则跨层通信会拖成幻灯片。
这些不是不能做，是做完之后你手上多了一个要自己维护的迷你游戏引擎，而不是一个更好用的装修工具。你只有一个人，工期要花在刀刃上。
02

Milanote 真正值得偷的三件事

一条都不需要坐标
STEAL 01

异构同权

Milanote 上一段文字、一张图、一个待办、一个链接、一个文件，都是同一个 note，享受同一套拖拽、选中、属性。

映射到你这儿：记录 / 约定 / 材料 / 费用 / 问题 / 证据，现在六个模块各有各的页面和展示。它们在底层应该是同一种物件的六种投影。这一条一旦落地，K03（contextLabel 是显示属性不是真数据）、K05（证据的 route 指向 camera）从根上就不会出现——因为它们本来就不是六个功能。

STEAL 02

Board 即交付物

Milanote 的 board 本身就是能分享出去的成品，没有「先整理再导出」这一步。

映射到你这儿：「给工长看的」和「自己看的」不该是两套数据 + 一个导出按钮。同一份 board，不同角色看不同的投影——工长看到的是今天要做什么，你看到的是这周有哪些没闭合的环。

STEAL 03 · 最值钱

延迟定型

Milanote 你扔一个东西上去，类型是后定的。

映射到你的真实场景：工人在现场拍张照、说句话，那一刻他自己也不知道这算证据、算问题、还是算材料到货。现在的产品逼他先选分类再填表——这是把 AI 该干的活，推给了工地上最忙的那个人。
正确顺序：先无摩擦捕获 → AI 给 provisional type + 置信度 → 用户一个动作改判。

这里没加新手势

四个方向键你本来就有。延迟定型不是往上堆新交互，是给老手势装新语义：平时它们切换矩阵，进入改判态时它们切换候选。骨架没动，能力翻倍。

状态就是通知

AI 处理完不弹窗、不挂红点。terrain 上多了一圈没消的 ring，就等于那里有一个 loop 没闭合。成本就是一个 ::after 的 CSS ring，但它同时满足你的判据：状态的改变本身就是回应，而且它改变了你下一步想去哪。

第二条是故意设的陷阱

点第二次「甩出」，AI 给的判定置信度只有 0.61，而且判错了。低置信度时 AI 会停在半路把选择权交回来——这就是 CopilotKit 的 interrupt，也是我上一轮提案里缺的那一块。

点一个格子看它的档位是怎么被你的行为推上去或拽下来的。

不是全局设置，是每个格子一份

全局五档自主度是个伪命题：你对「材料到货」可能闭着眼就让 AI 干，但对「费用变更」一定想亲自过目。档位应该跟着焦点单元走（18 组之一），而不是躺在设置页里。

档位是你行为的影子

初值全域 L1。某个格子里连续 3 次不问就采纳 → 自动升一档；发生一次改判 → 立刻拽回 L1（不降到 L0，否则来回横跳比不用 AI 还累）。这里是 CopilotKit 的 shared state 落地：AI 写的和用户录的必须是同一份 repository，不然会出现「AI 说材料到了但列表里没有」。

05

CopilotKit 那段：命名是对的，库用不了

协议能抄，实现不能抄

先认一句：你这刀扎得准。我上一轮说的「流程按人的环节切开、每个环节可开关 AI、随时脱离进入、五档自主度」，说的就是 Human-in-the-Loop + autonomy slider + interrupt/resume + shared state，只是我用了土话没用正式名。用了正式名的好处是——它变成了可以被讨论、被写进 PRD、被验收的东西，不再是「感觉这样比较聪明」。

但这个命名同时也暴露了我上一轮漏掉的两件事，下面补。

GAP 01

我没写「中断时上下文怎么保」

大部分人做 AI 产品只做 generate → render。CopilotKit 的精髓是 AI 跑到一半停下来问，你答完它带着你的回答接着跑，而不是从头再来。

落到你这儿：AI 判定一张照片属于「问题」但置信度只有 0.61 → 它停在半路，把这个节点挂起并派一个 ring 出来 → 你改判为「证据」→ 它带着「这是证据」这个既定事实继续走后面的流程（要不要通知工长、要不要关联同一批的其他照片），而不是重跑一遍理解。

这是五十毫秒和一秒的差别，也是「像个助手」和「像个复读机」的差别。

GAP 02

我没说 AI 的知识和产品的状态是不是同一份

CopilotKit 的答案是：必须是同一份。agent 读写的 state 和 UI 渲染的 state 是同一个对象。

落到你的项目，这句话是一条硬规格：AI 提议修改的东西，和用户手动录入的东西，必须落到同一个 repository。否则就会出现最让人失去信任的那种 bug——「AI 说材料到了，但列表里没有」；或者更糟的，「我在详情里改了预算，AI 还在拿旧的数算」。

这条做不实，前面所有 diagram 都白画。

技术口径

CopilotKit 用不了，但协议能抄

它给的能不能要说明
CopilotKit 本体不能React / Next.js 生态。你是原生 TypeScript + WXML/MINA，没有渲染层可以挂。
interrupt / resume 语义能是一个交互契约，跟框架无关。但它要求你先把 payload 定死：AI 挂起时应携带什么（暂定类型、置信度、候选集、已走过的步骤），恢复时应消费什么（你的判定）。
autonomy slider能但要改成 per-cell（见 §04）。全局滑杆是偷懒版。
shared state必须不是加分项，是及格线。见 GAP 02。
Generative UI暂缓服务端下发 UI schema 再渲染，小程序侧要自建渲染器，成本高、收益现在还说不清。等 §04 的契约跑通再谈。
ag-ui 协议能传输层的事件协议，框架无关。这是唯一能从 CopilotKit 生态里直接搬的现成东西——把事件名定下来（RUN_STARTED / TEXT_MESSAGE / TOOL_CALL / STATE_DELTA / INTERRUPT），前后端先对齐，实现以后换谁都行。
这份依然是纸上约定，没动任何源码。
关于我上一轮开在画布上的那份方案：这批结论全是时序的（甩出 → provisional → 改判 → 状态改变），静态框架表达不出来，所以我转回 HTML 这个形式，画布那份先搁着。

要你拍板的还是四件：
  1. 主动词定名——「巡场」还是 Explore（进入产品的第一个动词）
  2. 默认视野——进来看见的是当前工序（recenter）还是全部 42 格（zoom-to-fit）
  3. AI 唤起——长按甩出 vs 双指捏合（我倾向前者，因为它不新增手势且与 pan 不冲突）
  4. 探索与效率的配比——terrain 承担多少探索、Reading 面必须保持零探索
