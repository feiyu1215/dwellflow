# 装修同步 · 设计落地前置准备清单（先内容还是先设计）

日期：2026-10-02 深夜。依据：实读 `renovation-sync-miniprogram` 代码（14 页 / 24 个 core 模块 / 约 1.6 万行 TS / 多套测试）+ 已定案的巡场体系 + 外部策略稿融合结论。

---

## 一、代码里读到的四个关键事实

1. **全项目零图片资产。** 找不到任何 png/jpg/svg/webp——所有 UI 是纯 CSS 卡片。设计要的场景图从零开始，但反过来说：**没有任何旧图要兼容，接入是干净的**。
2. **空间维度已有一半数据。** `domain.ts` 的记录结构已带 `room` 字段（81/96/127/285 行），8 空间枚举（全屋/客厅/…）在。"点进房间看它的记录"这件事**数据上是通的**——好消息。
3. **归属模型还没实现。** 全代码搜不到 `scopeKind`——"这条记录属于全项目/某工序/归属待补"的三范围（M8B-3B）尚未落地。这是巡场的数据底座：**没有它，场景对象卡里的一切都是半猜的**，覆盖度上色、AI 定位候选都缺依据。
4. **AI 内核雏形是真的。** `ai-contract.ts` 已有任务类型、来源分级（project_fact/approved/unapproved）、材料核对字段、图片观察——"AI 起草、人拍板"的契约已在，前端三元素（巡/对象/呼吸点）接得上。

## 二、结论：先补内容与数据底座，设计前置只做三样便宜的事

**图不挡路，这是整个判断的支点。** 已定案的技术形态是"小程序只吃静态 2D 成品图"——接入接口就是**一张图 + 若干热点锚点坐标**。图什么时候好什么时候贴，替换的只是一个 image src 和一份锚点表，不碰任何逻辑。所以"做图"和"完善小程序"不是二选一，图可以并行慢跑，底座必须先走。

### 优先级排序

**第一优先：数据底座（这就是设计的地基，不是"不管设计"）**
- M8B-3A 缺陷收口（K01–K07，台账在案）——诚实性缺陷不清，场景里渲染的都是假数字；
- 3B 归属模型（scopeKind）——巡场三范围、对象卡、AI 定位候选全等它；
- 材料五态核对现有 `material-flow.ts` 的到货/入库链路与 PRD 五态（计划→采购→到货→使用→缺口）的差距，缺的补上。

**第二优先：总览页结构改造（用占位图，验证交互不验证美术）**
- 总览流程列表 → 勘测卷交互（拖拽磁吸+锚定展开，外稿 B1 的 HTML 验证版）；
- 对象卡 + 幽灵草案态 + 呼吸点（v4 料场原型已验证结构，落一页真代码即可）。

**第三优先：素材管线转正（唯一需要"自己做图"的事，但只先做一个 PoC）**
- 本机装 Blender，拿一个 CC0 客厅模型（Poly Haven 等）按手稿亮底风格渲**一张**成品——这一张决定 B 路线生死：渲染质量、耗时、风格能否统一。PoC 通过再批量，不通过就启动降级路线（勘测账本风，零插画）。
- 期间所有页面用现有 5 张 AI 风格预览图 + SVG 占位顶住，绝不阻塞上面两优先。

### 图的分工回答（你问"图自己做一做还是"）

| 图 | 谁做 | 何时 |
|---|---|---|
| 风格预览/占位图 | AI 生成（已有 5 张） | 现成 |
| 正式场景图（房子头图/客厅主景/料场等 4–6 张） | 我们自己：CC0 模型 + Blender 离线渲染 | PoC 后批量 |
| 户型图纸层 | openPlan3D 生成器（MIT） | 总览页需要时 |
| 图标/点缀零件 | Kitbitz CC0 手绘库 | 随用随取 |

**不需要买素材，不需要等设计师，也不需要现在批量出图。**

## 三、给下一版原型/开发的顺序单

1. 补 scopeKind 归属模型 + K 系缺陷收口（代码，第一优先）
2. 视觉令牌表/动效规格表/状态覆盖表（三份文本规格，外稿 §13，可与 1 并行）
3. 总览勘测卷 + 对象卡落 dashboard 真页（占位图）
4. Blender PoC 一张客厅渲染 → 定 B 路线或切账本风
5. 批量出正式场景图 → 替换占位 → v3/v4 交互形态全量铺开

一句话：**先让数据配得上场景，再让场景配得上数据。图是最后一公里，不是第一步。**
