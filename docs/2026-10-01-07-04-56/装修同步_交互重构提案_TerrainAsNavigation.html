Terrain as Navigation

装修同步 · 交互重构提案

八个参考案例到本项目的逐条迁移，以及一份冻结清单

你不需要借一座山。施工流程本身就是地形——纵向 7 个工序是路的延展，横向 6 个模块是路侧地块，格子里的计数是地块密度，past / current / upcoming 是路况。

三者相加已经是地形。缺的从来不是隐喻，是渲染方式：你把它画成了表格，所以它看着像表格，用户也就用看表格的态度对待它。

证据

三个站怎么描述自己

UNSEEN STUDIO · unseen.co 首页 H1 原文
"Drag to explore our world" —— 且导航第四项直接叫 World，与 Index / Projects / Contact 并列。世界是一个目的地，不是装饰层。交互提示为 Click & Hold。
BRUNO SIMON · bruno-simon.com 开场原文
"This is my portfolio. Please drive around to learn more about me and discover the many secrets of this world." —— 单一动词 drive 撑起全部。移动端映射明确：单指移动、双指转镜头与缩放、点击目标跳跃。
SAN RITA · sanrita.ca 案例自述
"Visitors do not click through a menu. They navigate terrain." —— 项目是嵌在地形中的 hotspot，由 trail 连接，且部分路段处于关闭养护状态。架构上分为持久的 3D canvas（挂在路由外不销毁）与轻量的项目页（HTML / SVG）。

这三句话指向同一件事：界面不是放东西的容器，而是你要在其中移动的场所。

映射

你的 terrain 词汇表

San Rita 需要自编一套 road / fishing spot / viewpoint 的行业黑话。装修这一行的词是现成的，全都在工地上真有人说：

Terrain 概念装修同步对应说明
Path（路）7 个工序设计 → 拆改 → 水电 → 泥木 → 油漆 → 安装 → 收尾。时间与顺序的真实延展
Region（地段）6 个模块记录 / 约定 / 材料 / 费用 / 问题 / 证据。路侧设施
Hotspot（点位）有内容的格子计数 > 0 即成点，可被停下查看
Unexplored（未开辟）空格子不是零，是"此处尚未记录"。措辞必须区分
Landmark（地标）卡点到货待核对 / 待复查 / 超时未确认。应当在地形上视觉凸起
Trail state（路况）past / current / upcoming走过、正在走、尚未开辟

顺带说明：这份映射天然满足你清单里的禁止项——不照抄山体纹理、不照抄配色、不用 GPS 地貌。地形是真的，不需要借。

主动词

不是一个页面它能unya

巡场

不是 Ask，不是 View。装修场景里真实发生、业主也认的动作是去工地走一圈。Bruno 用 drive，San Rita 用 navigate，你用巡场。围绕这一个动词定义三种手势：

DRAG
拖
在画布上连续移动视野。对应 San Rita 的 drag terrain、Bruno 的 drive。不再有"上一 / 下一"的离散步进
TAP
停
停在某个 hotspot，Reading 层从该点位展开。一次 curiosity 的成本仅一次点击
HOLD & SWEEP
圈
长按并划过一片区域，这片区域的事务直接成为 AI 的输入范围。手势本身就是 input，没有 submit 环节

结构

三层，各司其职

LAYER 01
Terrain
可 pan / zoom 的连续 7×6 画布。持久存在，切换不销毁。承担探索与定位
LAYER 02
Reading
从 hotspot 展开的轻量页。密度的反面：这里是高效阅读与操作区，零探索成本
LAYER 03
Agent
叠加在 Terrain 上的作用层。输入框不是控件，是被圈选出的区域本身

对应 San Rita 的架构决策：世界层持久、阅读层轻量。在你的小程序里落地为——画布组件不随页面切换销毁，Reading 用普通页面。

状态

显式状态机，不是孤立动画

借 Rive 的 state machine 思想，但只借用，不引入 runtime。下列七个 UI 状态需显式定义迁移条件，而非各页面自行其是：

loading
世界尚未成形。骨架式浮现，不是转圈
surveying
默认态。视野自动 recenter 到当前工序
focused
指针落在某 hotspot，其余 region 退后
reading
Reading 层展开，Terrain 层降为背景
collecting
长按圈选中。被扫过区域实时高亮
agent-active
AI 作用于该区域。范围可视，可中断
read-only
归档项目。缺乏ingu 全部交互动词，非仅靠颜色提示

motion

状态变化必须肉眼可感知

  • 进入即定位：视野自动 pan + zoom 到当前工序带。用户应当看见自己此刻站在哪里，而不是读一行"正在进行"。这是 motion carries state 最便宜也最有效的一处。
  • Terrain → Reading：镜头向该 hotspot 推进，其余区域同时缩小并淡出背景，Reading 面自点位位置展开。对应 Symphony of Vines 的"其余区域退去"。
  • 工序推进：路строка的高亮由一段连续扫过完成，而非标签替换。
  • loading：仿 San Rita 的分阶段浮现——先路成，再点位落，最后计数浮现。世界是被看见地建起来的。

可行性

这套东西在小程序里怎么落

不需要 WebGL，也不需要 Three.js。全部用 CSS transform + touch 事件即可：

  • 必须用 WXS 响应事件处理 touchmove 的 transform 更新。这是硬要求。若把 touchmove 送进 Page 的 JS 逻辑层，每帧都要跨逻辑层与渲染层通信，拖动手势会明显迟滞。WXS 是关键，不是优化项。
  • 画布用单容器 + transform: translate/scale，不用 movable-area，后者控制粒度不够。
  • 42 个格子属可接受 DOM 量。开启 will-change: transform，避免逐帧重排。
  • 幽灵一串：Zoom to fit、Recenter 作为基础操作而非高级功能（FigJam 原则）。

副作用

这不是跟缺陷修复抢时间，它就是修复本身

台账里那批缺陷，换个切入方式会自动消解：

缺陷为什么这条路能解
K01 只传 route画布上的 hotspot 天生携带 (stage, module) 坐标——不是补丁，是它的存在方式
K03 context 未真正携带圈选出的 region 是真实数据范围，不是显示属性
K04 composer 是假输入框长按 sweep 即 direct input。不需要假控件，因为它本来就是 input
K05 证据入口错指向 camera证据与设备各自成点位，入口直达
K07 WXSS 多轮追加重构窗口即清理窗口

因此这条路与 M8B-3A / 3B 不冲突——它是那批缺陷的解法，而非它的竞争对手。

冷水

最大的失败模式：把"办事"变成"逛"

San Rita 和 Bruno Simon 都是作品集，目的是让人逛。你这是个工具，人家来是为了办完事。

你的真实使用场景是：工地现场、可能单手、可能太阳反光，要在 15 秒内于水电工序记一条问题并附一张照片。此时任何"在路上移动"的心智成本都是负资产。

所以"world 与 reading 分层"的意义不在于视觉层次，而在于把探索成本与操作效率分开收纳。落到实施纪律：

  • Terrain 层承担探索，只服务于"我不确定现在该看哪儿"的时刻。
  • Reading 层必须做到零思考操作。进去 15 秒办完事的路径一点都不能变长。
  • 默认 auto-recenter 到当前工序，不让用户每次先逛一遍找位置。

冻结

以下本项目不动

  • 三个交互原语一个不动：二维 7×6 矩阵、四向手势、悬浮 AI 入口。本提案改变的是它们的实现方式，不是它们的存在。
  • 业务规则与数据模型一行不改：金额与数量的整数精度、版本规则、幂等、 backup 兼容。
  • 既有 120 项自动测试继续执行；构建与 miniprogramRoot 不变。
  • 轴交换（axesSwapped）保留，仅改为画布内的坐标重映射。
  • 不引入 WebGL / Three.js / Rive runtime / 新的 UI 组件库。
