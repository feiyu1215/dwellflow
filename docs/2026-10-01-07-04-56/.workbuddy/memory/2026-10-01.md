## 第四轮（用户问：Milanote 能结合空间吗 / 有什么创新交互 / CopilotKit HITL 那段）

### 我给的判断：**不引入自由空间（no free canvas）**
三条理由（A 是硬冲突，不是审美）：
- **A 手势槽已被征用**：用户冻结了「左右滑切模块 / 上下滑切工序」，而自由空间的最低门槛是单指 pan。同一根手指同一动作不可能既切模块又拖镜头。pan 吃 swipe → 骨架没了；swipe 吃 pan → 画布不能拖，那就不是空间只是静态图。第三条「先按编辑键换模式」是 One Primary Verb 的反面。
- **B 判据优先**：用户自己的判据是 Loop 不是 3D。得先证明 Loop 成立再谈容器。且 7×6 矩阵本身已是坐标系（工序纵轴 / 模块横轴 / 时态深度）——**空间被压进了语义**。San Rita 的真东西是「terrain 承担导航」，不是「terrain 要有海拔」。
- **C 小程序账**：Canvas2D 无 DOM 命中测试 → 42 hotspot 要自己写 hit-test / 相机 / 惯性 / 回弹 / 双指；touchmove transform 必须走 WXS。做完手上多的是「自己维护的迷你游戏引擎」，不是更好用的装修工具。

### Milanote 值得偷的三件事（一条都不需要坐标）
1. **异构同权** —— Milanote 上文字/图/待办/链接/文件都是同一个 note，同一套拖拽选中属性。映射：记录/约定/材料/费用/问题/证据 应是**同一种物件的六种投影**。落地则从根上消掉 K03（contextLabel 是显示属性）和 K05（证据 route 指向 camera）。
2. **Board 即交付物** —— 没有「先整理再导出」。映射：给工长看的 vs 自己看的是同一份 board 的不同投影。
3. **延迟定型 deferred typing（最值钱）** —— Milanote 扔上去类型后定。真实场景：工人拍张照那一刻自己也不知道算证据/问题/材料到货，现在逼他先选分类 = 把 AI 的活推给工地上最忙的人。正解：**慢捕获 → AI 给 provisional type + 置信度 → 用户一个动作改判**。

### 四个创新点
1. **Deferred Typing 复用已有四向手势**（平时切矩阵，改判态切候选）—— 不加新手势，是给老手势装新语义。
2. **状态即通知**：AI 处理完不弹窗不挂红点，terrain 上留一圈没消的 ring = 那里有 loop 没闭合。成本一个 CSS `::after`。
3. **Autonomy 落到格子粒度 + 行为学习**：不用全局五档，每个焦点单元一份。全域初值 L1；连续 3 次无误采纳升一档；任一次改判拽回 L1（**不降到 L0，避免来回横跳**）。L0→L3：建议 / 预填 / 自动+8秒撤销 / 自动。
4. **Undo 的形态是时间不是对话框**：8 秒视觉倒计时 arc 走完即固化，arc 本身就是 undo 窗口。

### 认下的两个洞（用户用 CopilotKit 正式名照出来的）
- 用户说的对：我上一轮那套「流程按人的环节切开 / 每环节可开关 AI / 随时脱离进入 / 五档自主度」= Human-in-the-Loop + autonomy slider + interrupt/resume + shared state，只是用了土话。用正式名的好处是**它变成可讨论、可写进 PRD、可验收的东西**。
