# 装修同步 R8-1F：v2 写入切换与迁移专项验证阶段记录

日期：2026-10-08  
状态：**实现与自动化验证完成；微信开发者工具真实本地数据迁移验收待执行。**

## 1. 本阶段目标

把 R8-1A 建立的 v2 envelope 从“只读预检能力”切换为小程序启动后的活动本地状态，同时保证迁移失败不会用空数据覆盖旧状态。本阶段完成 R8-1 的最后一个开发子批，不实现 R8-2 的 Space、Evidence 和巡场。

## 2. 已完成

- 小程序启动先执行 R8 v1→v2 迁移，再恢复中断任务和清理过期项目。
- 新旧状态使用独立 key；既有 v1 状态迁移成功后仍完整保留。
- 候选写入顺序固定为：发现来源、登记迁移前快照、内存转换、写入 v2、二次读取校验、切换活动指针、写入完成日志。
- v2 候选的 schema、迁移 ID、来源指纹、时间和状态内容均通过二次读取校验后才切指针。
- 同一来源迁移可幂等重试；切指针前中断时复用已经验证的候选，不重复生成业务状态。
- 来源在重试前变化时，来源指纹和 migrationId 会变化，旧候选不会被误当成本次结果。
- 存储空间不足、候选写入失败、候选读取损坏或活动指针异常时阻止切换，并保留失败日志。
- 指针已为 v2 但迁移日志未完成时，下次启动补齐日志，不重新迁移状态。
- `loadState` 按活动指针读取；损坏或缺失的活动 v2 会显式报错，不回退为空项目。
- `saveState` 在 v2 活动后只更新 v2 envelope，并执行写后二次读取；v1 不再被业务写入。
- 新安装直接建立 `fresh-v2`；合法的零项目 v1 状态也可迁移。

## 3. 存储状态

| key | R8-1F 行为 |
|---|---|
| `renovation-sync-state-v1` | 既有用户迁移后保留，只读，不自动删除 |
| `renovation-sync-state-v2` | 当前活动业务状态 envelope |
| `renovation-sync-active-state-schema` | 只有 v2 二次校验通过后才写 `v2` |
| `renovation-sync-migration-r8-v1-to-v2` | 记录 discovered 到 switched 或 failed |
| `renovation-sync-pre-r8-export` | 只登记旧状态 key、指纹、估算大小和时间，不包含密钥或原件正文 |

## 4. 关键取舍

1. **不双写。** 切换前只写 v1，切换后只写 v2，避免两个事实源继续分叉。
2. **不自动降级。** 活动 v2 损坏或缺失时阻断读写；自动回 v1 会隐藏 v2 新事实并制造数据丢失假象。
3. **旧 key 暂不清理。** 清理仍留到 R8-6 的完整备份恢复演练后决定。
4. **零项目是合法状态。** 项目列表为空不能被当作迁移损坏。
5. **本批只迁移 AppState。** Space、Evidence、Grant 和 Attention 的正式对象转换分别属于 R8-2 与 R8-5；本阶段不提前造数据。
