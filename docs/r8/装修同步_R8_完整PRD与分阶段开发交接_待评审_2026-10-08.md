## 2. 产品目标、范围与成功标准

把 R7 的空间拓扑与真实证据体验落进现有小程序，串起“项目概览—巡场—材料/问题—AI 初审—人工决定—返回现场”的完整流程，同时保留已有记录、约定、库存、费用、咨询、知识、备份与恢复能力。

已确认约束：低成本展示优先；不做雇人平台；负责人最终确认；AI 可以进入各业务环节，但不替人批准、付款、确认入库或关闭问题；巡场保留；7×6 棋盘退出；白/浅灰底与蓝色主操作；侧边半圆同时承担普通导航与 AI 入口。

R8 核心交付成功标准：

1. 人工路径可以独立完成，AI 不可用不阻塞业务；
2. 项目、身份、权限、证据、草稿和 AI 上下文不串项；
3. 新 UI 不破坏旧库存精度、费用事实、审批历史和备份能力；
4. 半圆能实际旋转、点击进入，巡场可滑动也可点击；
5. 每次保存有真实落点、失败状态与来源恢复；
6. 微信运行与设计原型分别验收，真实监控与语义评测单独标明证据等级。

不纳入核心完成门：云部署购买、真实摄像头采购、地图、3D、自动巡检、交易/支付执行、跨行业流程。上述事项保留扩展路径；真实多人云协作或设备接入启用前必须通过相应独立门。

## 4. 总体信息架构与导航

单项目直接概览；2～6 项目气泡/星图；更多项目卡片列表。项目概览包含当前重点、空间拓扑、继续巡场、本人待处理、项目资料和个人设置入口。

巡场横向切空间，纵向切施工阶段，日期/证据切片作为独立观察条件。材料、问题、费用、监控等属于当前项目内对象，从锚点、项目资料或半圆进入，不恢复为全局一级 Tab。

侧边把手可上下拖动，点击在当前页展开可旋转半圆；不出现中央浮卡。轻点节点直接进入，拖动只选择不触发业务。普通导航、AI 对话和当前对象专用 AI 都可成为节点，最多五项，更多进入明确列表。

来源返回保存项目、视图、空间、阶段、日期、对象与滚动锚点；目标失效按对象→空间→概览→项目入口回退。项目切换结束观看，草稿留在原项目。

## 6. R8-0：生产契约与迁移

沿用专项计划的 0A 外部依赖、0B 正式契约、0C 迁移回滚、0D 开工审查。

交付字段字典必须覆盖 Space、SpaceRelation、SpaceStageState、EvidenceAsset、EvidenceLink、PermissionGrant、AttentionItem、个人读态、ProjectViewState、OriginContext、ViewSession、FrameFreshness，以及 AI 写回校验上下文。每字段说明类型、必填、来源、校验、版本和兼容。

权限定义读取、草稿、提交事实、修订本人内容、管理与负责人专属动作。旧成员 scope 不自动扩展到证据、AI、监控或导出。迁移保护项目、原件、旧 ID、批准历史、库存事件、费用事实和作者；歧义归属进入待确认，不虚构空间关系。

## 7. R8-1：权限、项目壳与状态恢复

### 7.1 页面与交互

项目概览提供身份/阶段、当前最重要事项、空间舞台占位、继续巡场、待处理摘要和项目资料。尚未接入的空间区域显示真实建设状态，不塞假数据。头像进入个人设置，项目菜单进入项目管理；模型密钥只配置在服务端，客户端显示连接状态和允许的模型偏好。

### 7.3 数据与验证

ProjectViewState 不存正文、原件、token 或弹窗；草稿独立保存。角色视角只改变重点，不改变权限。全屋费用不会因空间筛选而误表示总额。

用例：0/1/2/6/7 个项目；A→B→A；重启恢复；对象删除、空间停用、项目归档/撤权；同机身份切换；项目 B 不显示 A 缓存。非负责人直达负责人动作入口被拒绝；标题、搜索、数量和缩略图均检查无权行为。

阶段风险：路由栈过深、旧入口被删、全局 currentProjectId 被异步操作误用。控制：动作提交时绑定显式 projectId，兼容旧链接并重新校验，不靠全局变量推断任务归属。

## 8. R8-2：空间、证据与巡场

### 8.1 功能与页面

空间管理支持添加、改名、顺序、可选关系和停用。空间阶段状态独立，成员可按授权提报、负责人确认的方式为推荐方案，具体默认待确认。

EvidenceAsset 管理原件与来源；EvidenceLink 连接记录、材料批次、问题和监控。查看器显示原件、时间口径、版本、ID 与关联，支持从缩略回原件；解除关联不会删除原件。原件修订形成新版本，旧业务引用继续指向旧版本。

拓扑是非比例示意。巡场以证据为主体，最多 1～3 重点锚点，胶片带提供空间/证据点击替代。无图、只有单据、未知归属分别呈现，不能用装修效果图填充。

### 8.3 验收与边界

## 9. R8-3：材料与问题人工工作台

### 9.1 材料

对象身份→批准基线→到货证据→差异→人工核对/AI 初审。核对明确材料与到货批次；品牌、型号、规格、数量逐项展示批准值、观测值、来源及 match/difference/unknown/conflict。人工保存独立核对记录，不自动入库、退货或付款。

采购、领用、退回、退货、损耗、盘点、费用审批和付款事实沿用现有规则，从工作台/项目视图进入。禁止为了新 UI 合并库存事件或费用事实。

### 9.2 问题

事实→待确认→预案版本→生效预案→处理提交→复查→负责人关闭/退回→可重开。家人提方案，施工提交处理，监管提复查意见；采用和关闭归负责人。前后证据显示位置/角度差异，不自动声称同位置或已解决。

## 10. R8-4：半圆导航与七类 AI

### 10.1 导航与对话

AssistHandle 拖动后抑制误点击，避免胶囊与底部按钮。EdgeDial 同页展开、连续旋转、松手吸附、点节点进入；取消只收起。没有中央浮卡或独立“进入”按钮。图标与盘面名称共同标识动作，AI 节点显式标 AI。

对话是另一种任务入口：用户输入→系统识别候选任务/对象→展示可编辑任务卡和资料范围→用户开始。存在多个对象时要求选择；不能猜错材料或跨项目抓取。语音可使用现有转写能力；若无实际服务则保留文本入口并说明不可用，不演示伪转写。

### 10.2 七类任务覆盖

| 任务 | 场景输入 | 人工复核与保存落点 | 禁止效果 |
|---|---|---|---|
| 材料核对 | 材料、批次、批准版本、单据/照片 | 四字段→MaterialCheckRecord | 自动入库、退货、批准 |
| 记录整理 | 当前记录和显式选取来源 | 事实/意见/缺口→记录新版本 | 改写原历史、把转述当事实 |
| 图片观察 | 选中证据、区域和项目信息 | 可见现象/疑点→观察记录或人工选建问题 | 工程合格判定、自动关闭 |
| 整改辅助 | 问题、预案、处理前后证据 | 拟预案或复查参考→独立草稿/记录 | 自动采用、确认整改有效 |
| 咨询整理 | 选中资料、问题或固定咨询回复 | 咨询草稿/回复映射 | 自动对外发送或代替专业意见 |
| 预算辅助 | 材料、库存、在途、批准与报价 | 参数人工确认→程序算估算版本 | 模型计算付款、自动采购 |
| 项目总结 | 固定空间/阶段/日期/截止快照 | 五分区人工复核→报告版本 | 自动发布、推进项目阶段 |

公共上下文含项目、身份权限、目标、来源快照和禁止动作；场景层维护专用 Prompt/输出契约；用户补充作为资料，不作为覆盖系统约束的指令。沿用已有机制，新增 context 层以实际复用为依据，不构建通用 Agent 框架。

### 10.3 任务与验收

| ID | 任务 | 验收重点 |
|---|---|---|
| 4A | 半圆微信实现与列表替代 | 真触摸旋转、节点命中、取消/返回、手柄拖动、小屏安全区 |
| 4B | 场景映射与对话任务卡 | 七类可达、对象歧义需选择、无跨项目输入 |
| 4C | 范围/运行/收起/取消 | 不自动发送资料；取消后晚到结果丢弃；可恢复真实任务状态 |
| 4D | 专用复核与幂等写回 | 来源存在、unknown/conflict、部分保存、权限/版本变化阻断 |

评测任务单独计费授权和限额；本计划不授权批量调用。公开/合成样本与真实数据分开，高能力 AI 初标不能冒充专业验证。R8 必须交付可复现评测配置和效果状态报告；没有专业样本时保留“未验证”，不得填写伪准确率。

## 11. R8-5：待处理、成员、监控与资料整合

### 11.1 待处理

来源为待负责人决定、分派本人、复查待补、AI 待复核/失败、本人上传失败。概览仅 1～3 重点，完整列表按项目筛选。阻断优先、本人决定其次、可靠逾期再次、最近变化最后；未知时间不显示逾期。

业务完成从对象读取；readAt/dismissedAt 是个人状态。投影去重键包含项目、目标、事件语义和版本规则；新事件是否重新提醒必须明确，不能永久沿用旧隐藏态。点击过期目标加载最新，无权不透露标题或数量。

### 11.2 成员与权限

成员详情→资源/动作/对象或空间范围→预览能看/能做/不能做→保存新版本。权限失败保留旧版本，冲突重新加载。负责人移交走独立流程并保证只有一个负责人。施工/监管是参与画像，不能靠视角自动获得授权。

撤权阻止新读取、搜索、导出、AI 输入/写回和观看；历史作者保留，外部已下载副本不能承诺收回。真实账号与接受邀请流程如未接入，必须标本地体验；不开展外部邀请。

### 11.3 监控与证据

绑定状态、会话状态、画面时间三层显示。开始观看必须有实际供应商能力，未配置时明确显示未接入。演示数据只能在显式体验模式下使用。

截图实际取得→预览设备/帧时间/空间→确认生成 camera_capture 证据→关联记录/问题→可另发 AI。离页/切项目/撤权结束取流，requestId 阻止旧回调。截图失败不建空证据，不支持则手动上传生成 manual_upload。真实供应商联调以账号、设备与用户费用决策为前置；未满足时该独立门阻塞，不阻塞其它功能。

### 11.4 任务与验收

|---|---|---|
| 5A | 待处理投影与读态 | 去重、重算、已读未完成、隐藏、新事件、撤权与目标变化 |
| 5B | 成员编辑/预览/移交 | 无隐式扩权、失败保旧版、唯一负责人 |
| 5C | 监控能力适配与会话 | 无设备诚实空态，退出/重连/旧回调正确 |
| 5D | 截帧/人工上传证据链 | 有实际原件、预览不计成功、重复确认幂等 |
| 5E | 项目资料整合 | 约定、预算、费用、咨询、知识、备份、导出稳定可达 |

### 12.3 缺陷与发布门

P0：数据丢失、串项目、越权、高影响误执行、迁移损坏；必须修复。P1：关键流程不可达、无法保存/返回、微信编译失败；必须修复。P2：局部视觉或非关键便利性问题；可登记影响、临时路径和后续任务。任何影响核心主张的未验证能力不得计为通过。

已登记 `UX-01`：空间、关系、方向和归属等结构化字段对普通用户操作过重，正式 UI 也尚未完成。后续采用“自然语言/语音描述→AI 生成结构化草稿→单页确认”的主路径；AI 不直接写正式事实，人工编辑退到更多设置，没有 AI 时保留最少字段的可用路径。该项在 R8-4 与正式视觉翻新时处理，不能因底层字段开发完成而关闭。

R8 核心验收通过不等于自动上线发布。真实多人、真实监控和真实 AI 语义效果分别出报告；缺外部依赖时标“未接入/未验证”，保持范围清楚。部署、外部体验邀请、上传审核和正式发布各按用户后续指令推进。

### 12.4 交付物

开发交接入口、最终页面/组件清单、类型与状态契约、数据升级/回滚说明、相关自动化结果、微信/真机检查记录、AI Prompt/评测版本记录、设备能力登记、未解决缺陷、已实现/演示/未验证能力表。

演示脚本以一条材料链和一条问题链为主，包含手工、AI 失败、人工复核和返回现场；不得用测试断言数代替产品效果。

## 13. 工程实施规范

继续使用现有原生小程序 TS/WXML/WXSS 和服务端结构。页面负责呈现与输入，领域层负责规则，存储层负责持久化，供应商适配层负责外部能力。先复用 `domain`、`store`、问题/材料工作流、精度、AI 契约和附件模块，再决定是否拆文件。

不建通用 Agent 平台，不为未来地图/3D引入无关依赖。新增依赖需说明必要性、现有实现替代、包体/兼容和许可。公共组件以真实重复职责为依据，不抽象只使用一次的业务规则。

每批先读对应规格和相关代码，确认改动范围，完成领域与视图后执行相关回归和类型检查。只有新失败或未解决风险才扩大测试。测试覆盖业务不变量、权限、迁移和异常；避免只复制实现细节的测试。

错误保留可恢复编辑并提供明确动作；日志不包含 API 密钥、播放 token 或原件正文。任务提交、写回和重试使用现有幂等机制。异步回调在提交前校验项目、目标版本和生命周期。

阶段结束同步：已完成、关键决策、验证环境与结果、未解决风险、下一阶段与阻塞条件。出现与 R7 设计明显偏离时先报告并记录变更，不能等用户发现。

## 15. 未来扩展的进入条件

云协作：真实身份、权限、存储、同步和撤权都可验证后启用。地图：多地址用户确有切换/监管成本后补设计。3D：稳定 Space/Evidence 模型与位置表达需求成立后，做示意渲染或模板；不把建模当质量事实。自动巡检：真实设备稳定、合法取帧与图片评测足够后，先做人工可复核提醒。全行业切换：装修流程已验证，再抽取领域模板，避免首版过度泛化。
