# R8-2A：空间模型与旧房间映射阶段记录

日期：2026-10-09  
状态：源码、自动化与用户微信端验收完成；用户于 2026-10-09 反馈验证正常。R8-2B 已另行实施。

## 1. 本阶段交付

- 新增稳定 `Space`、`SpaceRelation`、`SpaceStageState` 与 `LegacyRoomMapping`，均按项目隔离并带版本信息。
- 记录、记录版本、问题和摄像头绑定可选 `spaceId`；原有 `room` 文本继续保留，改名不会改写历史原文。
- 新增空间管理页，可新增、编辑、排序、停用、恢复空间，并查看记录数、进行中问题数和关系数。
- 旧标签只去首尾空白，不把“主卧”“卧室”“卧室1”模糊合并。用户可创建同名空间或明确关联已有空间。
- 已确认映射后来再次出现同一旧标签时，页面显示“沿用已确认归属”，仍需用户点击，不会静默迁移。
- 可登记相邻、通行、包含和其他关系及人工方向提示；拒绝跨项目、自关联、无向反向重复和包含环。
- 空间阶段状态独立于项目阶段。负责人可确认完成；无证据确认必须说明依据，已确认状态回退必须填写原因并形成新版本。
- 项目概览的“空间与现场”进入正式空间管理页，不再只展示临时房间标签汇总。

## 2. 关键决策

1. 旧数据采用显式人工整理，不在应用启动时自动归并。
2. 首批只有负责人管理空间、关系和阶段状态；成员提报等待后续正式授权编辑。
3. “负责人已确认完成”只记录业务决定，不代表专业工程验收。
4. 空间关系是非比例人工提示，不推断面积、距离或户型图。
5. 空间数据已进入 v2 本地状态，但可移植导出/恢复尚未扩展；页面已明确提示这一边界，R8-2E 前不得宣称完整跨设备备份。

## 4. 微信开发者工具手动验收

直接导入工程根目录：

`E:\workbuddy\2026-09-23-21-08-36\renovation-sync-miniprogram`

不要只导入 `miniprogram` 文件夹，也不要复制出第二份源码。由于 `app.json` 新增了页面，首次验收先关闭项目后重新导入，或清除编译缓存并重新编译。

验收顺序：

1. 从项目概览点击“管理空间与旧标签”，进入“空间与现场”。
2. 新增“主卧”和“厨房”，改名并上下排序；退出页面再进入，数据仍在。
3. 为两个空间登记关系，分别选择关系类型和方向；重复关系应被拒绝。
4. 给当前阶段登记“进行中”，再改为“负责人已确认完成”；没有证据且说明为空时应拒绝，填写说明后应成功。
5. 将已完成状态回退；说明为空时应拒绝，填写回退原因后应成功。
6. 若项目已有带 `room` 的旧记录、问题或设备，在“旧房间标签”中选择创建同名空间或关联已有空间；相似名称应保持独立候选。
7. 停用空间后，历史对象仍保留原 `spaceId`，空间出现在“已停用空间”；恢复后重新成为有效空间。
8. 归档项目后页面只读，新增、映射和状态修改入口不可用。
9. 关闭并重新打开小程序，确认空间、顺序、关系、状态和映射均保留。

手动执行前本记录只标“待验收”；只有在微信开发者工具中实际完成上述步骤后才能标通过。
