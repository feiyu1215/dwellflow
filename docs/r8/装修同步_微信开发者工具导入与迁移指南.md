## 一、结论先行

不需要把源码逐个复制到微信开发者工具，也不要新建另一份小程序工程。安装微信开发者工具后，直接导入以下现有工程根目录：

```text
E:\workbuddy\2026-09-23-21-08-36\renovation-sync-miniprogram
```

开发者工具读取根目录的 `project.config.json`，再根据其中的：

```json
"miniprogramRoot": "miniprogram/"
```

把 `miniprogram/` 识别为小程序运行目录。这样本地测试、服务端代码和小程序源码仍在同一个仓库中维护，但小程序编译和上传范围只从 `miniprogram/` 开始。

本次已经在 `project.config.json` 中明确启用 TypeScript 编译插件。当前小程序端没有引用第三方 npm 包，所以首次导入后**不需要执行“工具 → 构建 npm”**。根目录存在 `node_modules/` 是因为本地测试、类型定义和服务端需要，它不等于小程序端使用 npm。

## 二、官方文档带来的边界

### 2.1 普通小程序调试是当前主路径

当前项目应使用微信开发者工具的普通小程序流程完成编译、模拟器检查、Console/Network/Storage/AppData/WXML 调试、预览和真机调试。官方调试说明：

- [微信官方：小程序调试](https://developers.weixin.qq.com/miniprogram/dev/devtools/debug.html)
- [微信官方示例工程：project.config.json](https://github.com/wechat-miniprogram/miniprogram-demo/blob/master/project.config.json)（可核对 `miniprogramRoot` 和 `useCompilerPlugins: ["typescript"]` 的配置方式）

### 2.2 微信 AI 开发模式暂不合并

官方“小程序 AI 开发模式（beta）”是独立的内测能力：开发者把能力声明为原子 API、组件和 SKILL，由微信 AI 通过小程序 MCP 调用。它运行在区别于普通小程序的独立 JavaScript 环境中；官方页面当前明确提示代码提交暂未开放，并要求不要把该模式代码合入正式版本，以免影响普通版本发布。

因此，本项目继续采用已经完成的“普通小程序页面 + 自有服务端 + DeepSeek 固定任务工作流”。以后取得该内测资格时，可另开实验分支验证，不改动当前正式导入链路。

- [微信官方：小程序 AI 开发模式（beta）接入指南](https://developers.weixin.qq.com/miniprogram/dev/ai/guide.html)

| `renovation-sync-miniprogram/miniprogram/core/**/*.ts` | 领域逻辑、存储、AI 客户端、文件与业务规则 | 整个 `core` 目录保持原位 |


更推荐复制整个 `renovation-sync-miniprogram` 工程并继续从根目录导入，避免丢失测试、服务端和版本记录。

### 3.2 需要保留在本地，但不会作为小程序页面代码运行

| 路径 | 用途 | 是否放入小程序包 |
| --- | --- | --- |
| `package.json`、`package-lock.json` | 本地测试、TypeScript、服务端脚本 | 否 |
| `tsconfig.json` | 本地严格类型检查 | 否；开发者工具使用项目配置中的 TypeScript 插件 |
| `tests/` | 115 项自动测试 | 否 |
| `evaluation/` | AI 评测样本、脚本和报告 | 否 |
| `server/` | 本地业务、附件、身份和 AI 服务 | 否；必须作为独立后端进程运行 |
| `README.md`、`DOMAIN_CORE_MIGRATION.md` | 工程说明 | 否 |
| `m*.html`、`m*.png` | 静态设计预览与验收图片 | 否 |
| `node_modules/` | 本地 Node 依赖 | 否；已被 Git 忽略，也不应手工复制进 `miniprogram/` |

`miniprogramRoot` 限定了小程序编译根目录，因此把这些开发辅助文件保留在仓库根目录不会让它们自动成为页面代码。

### 3.3 严禁迁入小程序源码或提交仓库的内容

| 路径/内容 | 原因 | 正确位置 |
| --- | --- | --- |
| `.env` | 含模型密钥、服务访问凭证和将来的微信密钥 | 只留在服务端本机或部署平台的安全环境变量中 |
| `DEEPSEEK_API_KEY` | 小程序包可被用户取得，不能保存模型密钥 | 只由 `server/` 读取 |
| `WECHAT_APP_SECRET` | 属于服务端秘密 | 只由后端换取微信身份时使用 |
| `data/`、SQLite 数据库、附件原件 | 可能含用户资料，且不是客户端构建输入 | 服务端持久存储和备份目录 |
| `project.private.config.json` | 每台电脑和开发者工具的本地私有配置 | 由开发者工具生成；当前已在 `.gitignore` 中 |

小程序 AI 设置中填写的 `AI_SERVICE_TOKEN` 只是当前本地演示服务凭证，不能填写 DeepSeek 密钥。对外体验前，它也要改为真实微信登录会话和服务端权限校验。

## 四、首次导入步骤

1. 从微信官方渠道安装稳定版微信开发者工具。当前普通小程序不需要为 AI beta 安装 Nightly 版。
2. 打开工具并选择“小程序 → 导入项目”。
3. 项目目录填写：

   ```text
   E:\workbuddy\2026-09-23-21-08-36\renovation-sync-miniprogram
   ```

4. 尚未注册正式 AppID 时，选择工具允许的测试号/测试 AppID；注册后再在本机工具中关联真实 AppID。不要把真实 AppSecret 写入任何客户端配置。
5. 导入后确认详情页显示：项目类型为“小程序”，小程序目录为 `miniprogram/`，编译插件包含 `typescript`。
6. 首次点击“编译”。当前不执行“构建 npm”；只有以后小程序端真正 `import` 某个 npm 依赖时才需要安装并构建。
7. 在调试器依次检查：
   - Console：无启动异常、模块找不到或事件报错；
   - WXML：页面节点、样式和底部安全区正常；
   - Storage/AppData：项目数据和当前页面状态符合预期；
   - Network：只有开启 AI 或服务端流程时才应出现后端请求；
   - Sources：断点能定位到对应 TypeScript 源文件或编译映射。
8. 如果旧缓存导致页面或数据不一致，使用开发者工具的清缓存能力分别排查编译缓存与本地数据。清除本地数据会删除当前演示项目，执行前先确认是否需要导出备份。

## 五、后端与网络配置

### 5.1 只体验人工功能和完整 UI

不需要启动服务端。项目、记录、问题、材料、费用、咨询、备份及知识卡的当前演示流程主要使用微信本地存储和本地文件。

### 5.2 在同一台电脑的开发者工具中体验 AI

在 PowerShell 中从工程根目录运行：

```powershell
cd E:\workbuddy\2026-09-23-21-08-36\renovation-sync-miniprogram
npm run server
```

然后在小程序 AI 工作台连接设置中填写：

```text
服务地址：http://127.0.0.1:8787
服务凭证：.env 中的 AI_SERVICE_TOKEN（不是 DEEPSEEK_API_KEY）
```

开发阶段可以在开发者工具中关闭合法域名校验来连接本机回环地址；这只是本机调试方式，不能作为体验版或正式版配置。

### 5.3 预览二维码或真机调试 AI

手机中的 `127.0.0.1` 指向手机自己，无法访问电脑上的服务；而当前服务也只监听电脑回环地址。因此本轮不要为了扫码预览临时复制密钥到客户端，也不要把本机服务暴露到公网。

真机 AI 联调前应完成：

1. 部署一个 HTTPS 后端；
2. 在微信公众平台配置 request/upload/download 合法域名；
3. 使用真实微信登录会话替代固定演示 token；
4. 将附件、数据库和密钥放在服务端持久环境；
5. 再分别在 Android 和 iOS 验证请求、上传、下载、录音、文件选择和失败恢复。

这些属于后续“可对外体验”准备，不阻塞当前在开发者工具中检查完整 UI 与本地人工流程。

## 六、权限、隐私与审核前检查

工程已经在 `app.json` 中为 `scope.record` 写明录音用途。代码还使用了用户主动触发的媒体选择、聊天文件选择、文件打开、文件下载和剪贴板接口。导入编译不等于审核合规完成；在提交体验版或正式版前还需依据真实功能，在微信公众平台补齐小程序用户隐私保护指引、实际收集信息说明和服务器合法域名。

不要为了“看起来完整”在 `app.json` 中预先声明未使用的隐私权限。应以开发者工具的真实编译提示、平台隐私接口检测结果和最终启用功能为准，再补精确声明。

## 七、导入后第一轮验收顺序

建议按以下顺序定位问题，避免同时排查 UI、数据和 AI：

1. **启动门槛**：编译成功，首页能打开，13 个页面均可从入口进入。
2. **基础 UI**：导航、tabBar、表单、底部弹层、返回刷新、小屏滚动无阻断。
3. **本地人工闭环**：项目 → 记录 → 问题 → 材料/费用 → 咨询 → 备份。
4. **原生能力**：拍照/相册、录音、聊天文件、打开文件、剪贴板、导入恢复。
5. **AI 本机链路**：启动服务端后提交任务，确认任务 ID、轮询、人工复核和写回。
6. **真机差异**：具备 AppID 和设备后再检查安全区、键盘、权限弹窗、文件路径、录音和网络。
