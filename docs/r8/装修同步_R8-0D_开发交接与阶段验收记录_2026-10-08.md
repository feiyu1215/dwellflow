## 5. R8-1 建议开工拆分

R8-1 只做权限共用规则、项目壳和独立恢复，建议按以下顺序逐批提交：

| 批次 | 范围 | 依赖 | 完成门 |
|---|---|---|---|
| R8-1A | 增加 v2 envelope、活动 schema 读取器和只读迁移 dry-run；暂不切换写入 | 0B/0C | v1 可正常启动；转换报告稳定；失败不生成空项目 |
| R8-1B | ProjectViewState、OriginContext 与安全回退纯逻辑 | 1A | A→B→A、对象/空间/项目失效和同机身份隔离自动化通过 |
| R8-1C | 统一权限查询和动作策略，对齐本地/服务端语义 | 1A | 标题、计数、搜索、缩略与动作均有同一判权入口 |
| R8-1D | 项目入口：0/1/2～6/7+、搜索、排序、归档和撤权态 | 1B/1C | 一项目直达；7/20 项目不溢出；无权不泄漏元数据 |
| R8-1E | 项目概览壳、个人设置和项目资料稳定入口 | 1B～1D | 旧核心能力仍可达；不恢复棋盘/一级业务 Tab；空态诚实 |
| R8-1F | v2 写入切换及迁移专项验证 | 1A～1E | 二次读取校验、幂等、中断恢复、旧 key 保留；才允许设 v2 活动 |

这样拆分的原因：先让迁移和权限成为基础，再接 UI；项目入口完成后可独立验收；最后才切换写入，降低一次性改动导致数据不可读的风险。

## 6. R8-1 实施纪律

1. 页面只接收已判权的 view model，不直接遍历全局 AppState 后自行过滤。
2. 所有异步动作携带显式 projectId、identityId、target version 和 requestId，不从完成时的 currentProjectId 推断归属。
3. R8-1 不创建 SpaceRelation、Evidence 或真实 Camera 会话；这些对象只定义接口/占位，分别由 R8-2、R8-5 实现。
4. 旧入口在新稳定入口存在且回归通过前保留兼容路由，不先删功能。
5. 迁移转换写成纯函数；Storage 写入、活动指针与页面启动分层。
6. 角色视角只影响内容优先级；动作能否执行只看负责人策略和 PermissionGrant。
7. 每批修改后跑相关测试和 `npm run typecheck`；涉及存储/权限时跑完整 `npm test`。
8. 微信开发者工具和真机结果单独记录，不用 HTML 或 Node 测试替代。

## 8. 已定决策与未冻结事项

### 8.1 已定，可直接支持 R8-1

- 当前默认 `local_demo`；未来 connected 项目由服务端作为唯一事实源。
- 外部成员默认明确对象授权，`includesFutureObjects=false`；需要空间含未来对象时必须显式预览。
- 7+ 项目默认“本人有效待处理优先、最近活动其次”，并允许用户切换排序。
- v1/v2 分键，验证后切指针；R8-6 前不删除 v1。
- 权限默认收窄，不因新增 Evidence、AI、Camera 或 export 自动扩权。

## 9. 风险与控制

| 风险 | 影响 | 控制 |
|---|---|---|
| 直接把 AppState 全量换型 | 页面、备份、AI 和旧数据同时失效 | envelope/纯转换/兼容读分批推进 |
| 页面各自实现权限 | 数量或缩略先泄漏，动作口径不一 | 共用查询和动作策略先于 UI |
| currentProjectId 被异步回调误用 | AI、上传或监控串项目 | 任务固定 projectId＋生命周期校验 |
| v2 新写入后简单回 v1 | 新证据、授权或视图事实丢失 | 冻结写入、导出 v2、优先向前修复 |
| 为展示填充假空间/假通知/假设备 | 产品主张失真 | 空态和 demo disclosure，事实缺失就明确缺失 |
| R8-1 顺手重做材料/问题/半圆 | 范围扩散，无法定位回归 | 严格停在项目壳/权限/恢复，后续分阶段 |
